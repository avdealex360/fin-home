# Радикальная перестройка fin-home: ясный флоу 50/30/20

**Дата:** 2026-06-30
**Статус:** дизайн утверждён, миграции данных НЕ требуются (приложением ещё не пользовались — схему пересобираем начисто)

## Зачем

Текущее приложение реализует правило 50/30/20, но пользователь не понимает, как оно работает. Четыре конкретные боли:

1. **Не читается сквозной флоу — «что на что влияет».** План, Распределение дохода и Дашборд — три почти независимых представления одних и тех же денег. Распределил доход на категорию — её лимит не меняется. Записал расход — он влияет на дашборд, но не связан с тем, что «распределил».
2. **Вклад — изолированный остров.** Хранится в `Settings`, это просто баланс + калькулятор. Никак не связан со «Сбережениями» из 50/30/20, с «Копилками», с «Целями».
3. **Кнопка автораспределения 50/30/20 бесполезна.** Делит сумму группы поровну между категориями (`group_total / cats_in_group`), игнорируя фиксированные обязательства и реальные траты. Числа «с потолка».
4. **50/30/20 не видно там, где нужно учиться ему следовать** — при вводе расхода, в плане, в статистике.

Плюс новое требование: **раздел FAQ внутри приложения** с наглядным описанием всех сценариев.

## Ключевое решение: два «пота» вместо четырёх сущностей

Сегодня про «откладывание» говорят **четыре** пересекающихся понятия: группа *Сбережения* (50/30/20), *Копилки*, *Цели*, *Вклад*. По факту это **две** физически разные кубышки:

| | **Вклад** | **Копилка** («под матрасом») |
|---|---|---|
| Что | Реальный банковский вклад | Абстрактный отложенный конверт |
| Снять | **Нельзя** (только пополнять) | **Можно** — иногда тратим на мелкие цели |
| Проценты | Есть (капитализация) | Нет |
| Горизонт | Долгий, копится | Короткий, оборачивается |

«Цели», «Копилки» и группа «Сбережения» — это **одно и то же**, названное тремя словами. Схлопываем в одну сущность **Копилка** (расходуемый конверт). «Вклад» получает чёткую роль второй, *замороженной* кубышки, и его баланс реально растёт при распределении сбережений.

### Сквозной месячный флоу (что на что влияет)

```
Доход  ─►  Распределить (экран зеркалит 50/30/20):
            ├─ Нужды (50%)       → лимиты категорий needs
            ├─ Желания (30%)     → лимиты категорий wants + копилки(wants)
            └─ Сбережения (20%)  → Вклад (заморожено) + копилки(savings)

Расход        ─► уменьшает остаток категории и её корзины 50/30/20
Трата из копилки ─► уменьшает баланс копилки
Пополнение вклада ─► баланс только растёт; виден прогноз с %
```

План — единый источник правды: и Распределение, и Дашборд читают цифры из него.

## Изменения модели данных

Данные не сохраняем — таблицы пересоздаются. Миграцию-перенос не пишем; обновляем `models/__init__.py`, схему БД (drop+create в dev / новая alembic-ревизия «reset» для прод), `seed.py`, сериализаторы и API.

### Удаляем
- `Goal`, `GoalContribution` — роль покрыта копилкой с `target_amount`.
- Категории группы `savings` как расходные — больше не нужны (сбережения уходят во Вклад/копилки, а не в категорию с лимитом).

### Копилка (внутреннее имя `SinkingFund` сохраняем ради меньшего blast-radius; в UI — «Копилка»)
```
name, icon, color
group                 : 'wants' | 'savings'        # корзина 50/30/20
target_amount         : Decimal | None             # бывшая «Цель»
target_date           : date | None
monthly_contribution  : Decimal                    # ориентир для автораспределения
current_amount        : Decimal
is_rolling            : bool
is_active             : bool
```
Поля `category_group` и `linked_category_id` убираем (заменены на `group`).
Действия: **Отложить** (+) и **Потратить** (−, уже поддержано через `Transaction.is_sinking_fund_spend` + `fund_id`).

### Вклад — промоут из настроек в сущность
- Новая таблица `DepositContribution (id, amount, date, source)` — журнал пополнений.
- Параметры вклада (`balance` стартовый, `rate`, `cap_day`, `start_date`, `rate_schedule`, `monthly_target`) остаются в `Setting` (одиночный вклад).
- Баланс **только растёт**: действие «Пополнить вклад» добавляет запись и увеличивает баланс. «Снять» убираем из UI.
- Калькулятор прогноза с капитализацией (`deposit_calc.py`) остаётся как есть.
- `DepositSnapshot` остаётся для истории баланса (необязательно).

### Распределение дохода
- `IncomeAllocation.fund_id` → копилка (как раньше).
- Добавляем адресат «вклад» полем `to_deposit: bool` на `IncomeAllocation` (`category_id`/`fund_id` тогда `NULL`). Пополнение вклада через распределение создаёт `DepositContribution(source='allocation')`.
- Уровни L1–L4 заменяем на три корзины 50/30/20 (см. ниже).

## Экран «Распределение дохода» (`AllocationSheet`)

Сейчас — 4 абстрактных «уровня». Заменяем на **зеркало 50/30/20** — три секции:

- **Нужды (50%)** — категории `needs`, предзаполняются плановыми лимитами.
- **Желания (30%)** — категории `wants` + копилки `wants`.
- **Сбережения (20%)** — **Вклад** + копилки `savings`.

Сверху каждой секции — счётчик «распределено / целевые N% от дохода» с цветовым индикатором отклонения. Это попутно выносит 50/30/20 в сам флоу распределения (закрывает боль №4 ещё и здесь). Глобальный счётчик «к распределению» остаётся.

## Автораспределение (боль №3) — переписываем

### В распределении дохода (кнопка «Распределить по плану»)
Вместо деления поровну — **заполнение по плану и известным суммам**. Для дохода I:
1. Нужды: сумма плановых лимитов `needs` + фиксированные плановые расходы + минимальные платежи по долгам.
2. Желания: плановые лимиты `wants` + `monthly_contribution` копилок `wants`.
3. Сбережения: `monthly_target` вклада + `monthly_contribution` копилок `savings`.
4. Остаток (если `I` больше суммы) → в выбранный по умолчанию адресат (вклад). Если суммы превышают `I` — пропорционально ужимаем и предупреждаем.
Каждая секция показывает свою сумму против 50/30/20-цели с дельтой. Никакого равного деления.

### В плане (кнопка «Пересчитать 50/30/20» → «Подогнать под 50/30/20»)
- Сверху — **живой 50/30/20-метр**: три бара «распределено по группе / цель (50/30/20 от ожидаемого дохода)», обновляются при правке лимитов.
- Кнопка масштабирует текущие лимиты внутри каждой группы пропорционально, чтобы суммы групп попали в цель (сохраняет относительные размеры). Равное деление — только фолбэк, когда лимитов в группе ещё нет.

## 50/30/20 везде (боль №4)

- **Расход (`TxForm`):** чипы категорий **сгруппированы** под заголовками Нужды/Желания. При выборе категории — мини-полоса «осталось в [корзине]: X из Y» за текущий месяц, чтобы видеть давление на корзину прямо в момент траты.
- **План:** живой 50/30/20-метр (см. выше).
- **Аналитика:** новый блок «Факт 50/30/20» — фактическое распределение месяца (нужды/желания/сбережения в % и ₽) против идеала 50/30/20; тренд savings-rate уже есть — оставляем и подписываем целевую линию 20%.
- **Дашборд:** три бара корзин уже есть; добавляем подпись «% от дохода / цель %».

## Раздел FAQ / «Как это работает» (новое требование)

Новый маршрут `#/faq` (вход — со страницы «Ещё» и из онбординга). Набор наглядных карточек-сценариев, каждая: короткий заголовок, 2–4 шага, маленькая встроенная иллюстрация/диаграмма (SVG или схема на CSS). Сценарии:

1. **Как устроены деньги** — схема двух потов (Вклад vs Копилки) и корзин 50/30/20.
2. **Записать доход и распределить** — как доход растекается по трём корзинам.
3. **Записать расход** — как трата давит на корзину/категорию.
4. **Копилки: отложить и потратить** — конверт «под матрасом».
5. **Вклад: пополнить и следить за ростом** — заморожено, только растёт, прогноз с %.
6. **Что такое 50/30/20 и как ему следовать** — смысл правила, где в приложении видно отклонение.
7. **Спланировать месяц** — ожидаемый доход → лимиты → 50/30/20-метр.
8. **Закрыть месяц** — перенос остатков лимитов.

Контент — статический (компонент со списком сценариев), без бэкенда. Тексты на русском, mobile-first, в стиле существующих токенов (`app.css`).
