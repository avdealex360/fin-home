# ТЗ: Веб-приложение «Семейный бюджет»
 
**Версия:** 1.0  
**Дата:** июнь 2026  
**Среда:** VPS 1 vCPU / 1 GB RAM / 10 GB SSD, Docker, рядом с Amnesia VPN
 
---
 
## 1. Цель и контекст
 
Приложение для двух человек (семейная пара): ведение доходов и расходов по факту начиная с текущего месяца, планирование бюджета по методу 50/30/20, контроль долгов, динамика накоплений, советы в реальном времени.
 
Исторические данные не вносятся — старт с нуля с текущего месяца.
 
---
 
## 2. Ключевые требования к стеку
 
### Почему важны ограничения железа
 
VPS делит ресурсы с Amnesia VPN (Docker-контейнер). Приложение должно потреблять **не более 150 MB RAM** в idle и **не нагружать CPU** в фоне. Хранение данных — SQLite (один файл, легко переезжает на другой VPS).
 
### Рекомендуемый стек
 
| Слой | Технология | Обоснование |
|---|---|---|
| Backend | **Python + FastAPI** | Лёгкий, async, минимум RAM |
| База данных | **SQLite** (через SQLAlchemy) | Один файл, нет отдельного процесса, перенос = `cp` |
| Frontend | **HTMX + Jinja2 шаблоны** или **Vue 3 SPA (Vite build)** | HTMX проще деплоить, Vue — если нужна реактивность |
| Авторизация | HTTP Basic Auth или единственный токен в `.env` | Два пользователя, никакой регистрации |
| Контейнер | **Docker Compose** (один сервис) | Соседствует с VPN-контейнером |
| Reverse proxy | **Caddy** или уже стоящий nginx | TLS автоматически, минимум конфига |
| Бэкапы | `cron` → `sqlite3 .dump` → файл + опционально S3/rclone | |
 
### Альтернатива (если хочется совсем просто)
**Node.js + Express + better-sqlite3 + vanilla JS** — меньше зависимостей, быстрый старт.

## 3. Структура данных
 
### 3.1 Категории расходов (преднастроены, расширяемы)
 
**Нужды (50%)**
- Аренда жилья
- Продукты и быт
- Транспорт
- Здоровье и лекарства ← отдельная строка
- Кот (корм, наполнитель, плановые расходы) ← отдельная строка
- Ветеринар / операция кота ← разовые/крупные
- Связь и интернет
- Яндекс Сплит (обязательный платёж)
- Кредитка Тинькофф (погашение)
**Желания (30%)**
- Рестораны и доставка
- Подписки и развлечения
- Одежда и уход
- Спорт и хобби
- Подарки
- Буфер (прочее)
**Сбережения (20%)**
- Подушка безопасности (накопительный счёт)
- Вклад (машина)
- Досрочное погашение долгов
### 3.2 Источники дохода
- Зарплата (основной, привязан к курсу EUR/USD)
- Доход партнёра (нерегулярный, вводится по факту)
- Прочие поступления
### 3.3 Долги и обязательства (отдельная сущность)
```
debt {
  id, name, total_amount, remaining, monthly_payment,
  interest_rate, type (credit_card | split | loan),
  start_date, target_close_date, is_closed
}
```
 
### 3.4 Цели накоплений
```
goal {
  id, name, target_amount, current_amount,
  deadline, monthly_contribution, linked_account_name
}
```
 
Преднастроенные цели при первом запуске:
- Подушка безопасности — цель 150 000 ₽ (минимум), затем 500 000 ₽
- Машина — цель 1 000 000–2 000 000 ₽, дедлайн конец 2027
- Взнос на квартиру — горизонт 5+ лет, сумма TBD

## 4. Функциональные модули
 
### 4.1 Дашборд (главный экран)
 
**Верхняя панель — текущий месяц:**
- Общий доход (факт / план)
- Потрачено всего
- Остаток до конца месяца
- Норма сбережений % (факт vs цель 20%)
- Статус вклада (текущий баланс с учётом процентов)
**Три блока 50/30/20:**
- Для каждого блока: лимит по плану / потрачено факт / остаток / % использования
- Цветовая индикация: зелёный (<80%), жёлтый (80–100%), красный (>100%)
**Блок долгов:**
- Кредитка Тинькофф: остаток, дата льготного периода, предупреждение если приближается
- Яндекс Сплит: остаток, следующий платёж, дата закрытия
- Прогресс-бары по каждому долгу
**Блок целей:**
- Прогресс по каждой цели
- Сколько месяцев до достижения при текущем темпе
**Советы (AI-блок, см. п. 5)**
 
### 4.2 Внесение операций
 
Быстрая форма на главном экране или отдельная страница:
- Тип: расход / доход / перевод в сбережения
- Сумма
- Категория (выпадающий список с поиском)
- Дата (по умолчанию сегодня)
- Комментарий (опционально)
- Кто вносит (пользователь 1 / пользователь 2) — для понимания кто что тратит
**Важно:** ввод должен быть удобен с телефона (крупные кнопки, числовая клавиатура).
 
### 4.3 Месячный план
 
Страница настройки бюджета на месяц:
- Ожидаемый доход (вносится в начале месяца)
- Автораспределение 50/30/20 с возможностью скорректировать лимиты вручную
- Плановые крупные расходы месяца (операция кота, разовые платежи)
- Плановые взносы по долгам
При наступлении нового месяца — уведомление/предложение заполнить план.
 
### 4.4 Аналитика и история
 
**По месяцам:**
- Таблица: план vs факт по каждой категории, отклонение в ₽ и %
- График: доходы / расходы / сбережения по месяцам (накопительно)
- Топ-5 категорий расходов
**По категориям:**
- Динамика конкретной категории по месяцам
- Средний расход за последние N месяцев
**По долгам:**
- История платежей
- Прогноз даты закрытия
### 4.5 Вклад и накопления
 
Отдельный раздел для работы с вкладом:
- Текущий баланс (вносится вручную раз в месяц или рассчитывается)
- Ставка (сейчас 17,5%, будет меняться)
- График роста: факт + прогноз до дедлайна
- Расчёт: сколько нужно вносить ежемесячно чтобы достичь цели к дате
- Интерактивный калькулятор: меняешь взнос → видишь итог
### 4.6 Настройки
 
- Имена пользователей
- Основная валюта
- Курс EUR/USD (вводится вручную или через открытое API)
- Управление категориями (добавить / скрыть)
- Управление долгами (добавить новый, отметить закрытым)
- Управление целями
- Экспорт данных (JSON / CSV)
- Смена пароля

## 5. Советы в реальном времени
 
Не нужен внешний AI. Реализуется как набор правил (rule engine) на бэкенде:
 
### Триггеры и тексты советов
 
| Ситуация | Совет |
|---|---|
| Потрачено >80% лимита категории, а месяц не кончился | «В категории "Рестораны" осталось X ₽ до конца месяца» |
| Кредитка: льготный период заканчивается через 7 дней | «Погасите кредитку до [дата] чтобы избежать процентов» |
| Норма сбережений <10% в середине месяца | «Вы откладываете меньше 10% — попробуйте перенести X ₽ из "желаний" в накопления» |
| Доход партнёра не внесён >10 дней | «Не забудьте внести доход за текущий месяц» |
| Вклад не пополнялся >30 дней | «Вклад на машину не пополнялся месяц — добавьте хотя бы X ₽» |
| Крупная разовая трата >20% месячного дохода | «Большая трата X ₽ — проверьте, не нужно ли скорректировать план на месяц» |
| Долг закрыт | «Кредитка закрыта! Теперь [сумма платежа] ₽ можно направить в подушку безопасности» |
| Подушка достигла цели-минимум | «Подушка безопасности 150 000 ₽ собрана! Следующая цель — 500 000 ₽» |
| Расходы на здоровье >20 000 ₽ в месяц | «Расходы на врачей выросли — может стоить посмотреть ДМС?» |
 
Советы показываются на дашборде в блоке, приоритизируются по срочности. Максимум 3 активных совета одновременно.

## 6. Архитектура и деплой
 
### 6.1 Docker Compose
 
```yaml
version: '3.8'
services:
  budget-app:
    build: .
    restart: unless-stopped
    ports:
      - "127.0.0.1:8000:8000"  # только localhost, наружу через nginx/caddy
    volumes:
      - ./data:/app/data       # SQLite файл + бэкапы
    environment:
      - APP_SECRET=...
      - APP_PASSWORD=...
    mem_limit: 256m            # жёсткий лимит памяти
    cpus: '0.3'                # не больше 30% ядра в среднем
```
 
### 6.2 Переезд на другой VPS
 
Весь перенос = три команды:
```bash
# На старом VPS
tar -czf budget-backup.tar.gz data/ docker-compose.yml .env
 
# Скопировать архив на новый VPS
scp budget-backup.tar.gz user@new-vps:~/
 
# На новом VPS
tar -xzf budget-backup.tar.gz && docker compose up -d
```
 
### 6.3 Бэкап данных
 
Скрипт в `cron` раз в день:
```bash
sqlite3 /app/data/budget.db ".dump" > /app/data/backups/budget_$(date +%Y%m%d).sql
# Хранить последние 30 дней, старые удалять
find /app/data/backups -mtime +30 -delete
```
 
### 6.4 Потребление ресурсов (целевые значения)
 
| Параметр | Цель |
|---|---|
| RAM в idle | < 100 MB |
| RAM под нагрузкой | < 200 MB |
| CPU в idle | < 1% |
| Размер БД за год | < 5 MB |
| Время отклика страницы | < 300 ms |

## 7. Безопасность
 
- HTTPS обязательно (Caddy — автоматический сертификат Let's Encrypt)
- Авторизация: единый логин/пароль из `.env` (HTTP Basic Auth или простой JWT)
- Данные хранятся только на VPS, никакого облака
- `.env` не попадает в git (`.gitignore`)
- Порт приложения закрыт снаружи (только через reverse proxy)

## 9. Специфика под вашу ситуацию
 
### Категории, которые нужно завести сразу
- **Кот — плановые** (корм, наполнитель, когтеточки и т.д.) — месячная статья
- **Кот — ветеринар** (операция и плановые визиты) — отдельная статья, можно поставить бюджет на квартал
- **Здоровье и лекарства** — отдельно от «быта», чтобы видеть реальные расходы
- **Курс EUR/USD** — доход вносить в рублях по факту получения, но хранить привязку к базовой сумме в EUR для понимания реального дохода
### Первые шаги после запуска
1. Заполнить план на текущий месяц (ожидаемый доход)
2. Создать два долга: кредитка (44 000 ₽, ставка 29%) и Сплит (92 000 ₽, 0%)
3. Создать цели: подушка (150 000 ₽), машина (1 500 000 ₽)
4. Начать вносить операции — хотя бы крупные (аренда, продукты, рестораны)
5. Через 2 недели первые данные уже дадут понимание куда уходят деньги

## 10. Что НЕ нужно делать (антипаттерны для этого железа)
 
- PostgreSQL — избыточно, SQLite достаточно для 2 пользователей
- Redis — не нужен кэш при такой нагрузке
- Celery / очереди задач — все задачи синхронные или простой cron
- Отдельный фронтенд-сервер (nginx для статики) — FastAPI отдаёт статику сам
- WebSocket для «реального времени» — обычный polling раз в минуту достаточно
- Микросервисы — один контейнер, один процесс
